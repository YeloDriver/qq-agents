# QQ 回复漏调用发送工具的自动纠偏方案

状态：设计草案，未实现、未启用、未进行真实模型或 QQ 验收。本文只讨论运行时方案；先前独立增加的自然聊天与显式投递提示已撤回，下面的观察与纠偏机制仍未实现。

## 1. 问题与源码基线

已观察到 Codex 回合正常 `completed`，原生 `agentMessage` 有普通正文，却没有调用 QQ 发送工具；用户在上下文中提醒后恢复使用发送工具。这不能确证上游根因，也不能证明所有无发送回合都是故障。正常沉默、只做工具工作、等待消息和投递未知都必须保留。

以下是当前源码可核实的边界，后文新增字段、接口、工具及配置均为建议：

## 2. 信号分层与覆盖范围

方案有两条路径：已经登记回复决定却漏调用发送工具，以及没有登记决定、只输出普通文字的可疑回合复核。前者能证明登记过回复选择，后者只能证明需要复核，不能认定正文应当发送。两条路径都不要求每次被唤醒都说话，都须证明正常完成、没有发送调用及没有投递尝试。

| 信号                                                         | 能证明什么                                                             | 用途                                                                               |
| ------------------------------------------------------------ | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 适配器归一化的终态、原生回合 ID、会话与连接代际              | 当前确切回合正常结束，工具通道已排空；不证明应该回复                   | 纠偏硬条件                                                                         |
| 运行时登记的发送工具调用、进行中调用数、发送器回执与 attempt | 是否尝试调用、是否可能已经发出；成功必须以确认回执为准                 | 纠偏硬条件与防重                                                                   |
| 经过运行时校验的回复决策回执                                 | 模型确实通过工具提交了一个绑定本轮输入的决定；不证明模型的内容判断正确 | 推荐的窄触发依据                                                                   |
| 后续经管理员明确配置的结构化回复规则                         | 指定范围和事件类型下存在回复要求；不扩大发送权限                       | 可选扩展，需另行确认                                                               |
| 非空的最终 `agentMessage` / assistant 文本                   | 仅证明模型输出了文字，不能证明发送意图                                 | 与有效新输入、零工具调用和显式配置组合时可触发一次复核；不能单独触发发送或解除保护 |
| 模型声称“已发”“我要回复”或“我保持沉默”                       | 仅证明模型输出了这些文字                                               | 不用正文语义判断发送、沉默或授权；不能确认投递                                     |
| 私聊、提及、问号、无动作次数、读水位                         | 有输入或曾被唤醒，不证明回复决定                                       | 不单独触发                                                                         |

推荐新增可选桥接工具 `qq_reply_decision`，接受有限枚举 `send` / `silent` / `defer`、本轮 `eventIds` 和可选枚举原因；不接受自由正文、目标聊天、角色或权限参数。运行时从 `ctx` 取身份，校验这些事件属于当前完整展示的有效新输入，并生成绑定 `turnId`、输入代际、配置代际及来源集合的回执。`silent` / `defer` 可在实际发送前撤销同一回执的 `send` 决定；不能撤销投递 attempt 或解除锁定。

这个工具登记的是模型选择，可信部分是“确实登记、绑定正确”，不是把模型选择升级为外部事实。它不推进已读水位，不恢复回复额度，不授予联网、外发或披露权限。历史回放、handoff、Self、旧笔记、对端机器人发言及工作审批结果不能登记为新的人工回复要求。首版仅支持普通聊天中经过现有人工输入校验的消息。

**覆盖本次故障：** 模型连决策工具也漏调用时，不能要求已有 `send` 回执才恢复。建议另设显式选项 `reviewUnclaimed`：在批准聊天范围内，针对有效、完整展示的人类新输入，且本轮零工具调用、正常完成并输出非空最终普通文本的回合，追加一次固定复核提醒。模型可以在这次复核中选择发送，或登记 `silent` / `defer` 后结束；运行时绝不直接转发第一轮正文。

缺省关闭此选项时，这类回合只观察。开启后也不使用“所有私聊必须回复”或正文语义分类器：私聊/提及只是组合条件中的输入来源，普通文字只说明有复核候选。它会对部分本来想沉默却没明确登记的回合产生一次额外模型请求，因此须单独选择范围、说明额外用量并统计误报；不能保证复核后一定发送。已做工具工作、只有空输出、历史收尾、已登记沉默或延期不进入该首版路径。

## 3. 架构与回合状态

建议在 `TurnRunner` 正常完成分支、撤销能力和 `contexts.finish` 之前加入评估器；生成失败仍走失败分类分支。另设小型 `reply-correction` 模块处理纯条件判断、状态和固定提醒，避免把协议解析或 QQ 投递放进评估器。

后端契约增加可选的终态证据回调及 `canContinueCompletedTurn` 能力，默认为不支持。证据只含版本、原生回合 ID、完成状态、输出类型/非空标记、通道是否排空和代际；不把正文送入纠偏日志。旧适配器允许继续运行，但不能因 `run()` 正常返回而自动宣称支持纠偏。

运行时增加本轮专用的完整计数与状态：发送工具调用数、工具进行中数、终态证据、回复决策回执、纠偏状态及共享自动续接额度。计数在进入调用、任何 `await` 之前登记，包含参数错误、拒绝及嵌套 `bridge_call` 的实际工具名；不能依赖截断的 `ctx.toolCalls`。发送器独立记录本轮全部投递预留，覆盖文字、媒体、文件和 QQ 操作。

```text
running → normal-completed → evaluate
                              ├─ 不满足 → finalize
                              └─ claim → verify-native → correcting → finalize
running → classified-failure → generation-recovery（共用 claim）→ finalize
```

纠偏是同一个桥接回合的一次后端续接，保留 `ctx.turnId`，记录第二个原生回合 ID及其用途。它不生成新唤醒，不重跑 `contexts.prepare` / `conversations.begin`，不提前释放 `runtime.running`，最终只收尾一次。原始生成成功仍是成功；纠偏状态单独记录，不把漏工具伪装成生成错误。

### 3.1 精确触发条件

所有条件同时成立才可进入 `claim`，否则终结本轮或仅记录观察：

1. 管理员显式启用 `correct`，角色及当前聊天均在批准范围内；后端适配能力与证据版本支持。
2. 普通 QQ 人工输入回合，排除 `@subject`、`@work:`、游戏、定时任务、主动意图及内部控制投递。触发依据满足以下二者之一：A，有仍有效的本轮 `send` 决策回执；B，管理员显式开启 `reviewUnclaimed`，本轮由新的人工私聊或直接提及唤醒，完整新输入仍有效，所有工具调用数为零，原生终态报告非空最终普通文本，且无有效 `silent` / `defer` 决定。B 只生成内部复核资格，不合成 `send` 决策回执。
3. 最后一个执行尝试有匹配的正常完成证据；既非失败、取消、超时，也非未知终态。原生工具通道及本地工具调用已排空。
4. 整个桥接回合发送工具调用数为零，`confirmedSends` 为零，`deliveryAttempted` 为假，`pendingDeliveries` 为零，且无本轮持久化投递预留。任一计数或账本证据缺失时保守跳过。
5. 原会话仍兼容、未退休，角色、`connectionId` / 账号、`backendId`、会话 ID、配置与连接代际未变化；能力仍有效，所有当前权限和预算检查通过。
6. 没有生效的静默、休眠/等待决定、待披露审批、保护阻断或已消费的恢复投递锁；新输入没有使决策回执或复核资格失效。
7. 原 deadline 尚有最低续接余量，共享自动续接额度尚未消费；原生提交前再次验证上述条件。

任何发送工具曾被调用，即使参数解析失败、语气提醒、权限拒绝或没有产生 attempt，也不属于本方案的“漏调用”；由当前工具错误处理完成，不能再套一次纠偏。只做工具工作但没有 `send` 回执，或显式选择 `silent` / `defer`，同样不触发。复核路径的任何工具调用、空输出、非新输入回合都只记录观察。已有 `sent`、`pending`、`unknown`、`failed` attempt 或部分连发时均禁止纠偏，不能以失败回执证明可以重新投递。

历史遗留的未知回执继续遵守原发送防重规则。首版若无法证明它与本轮决策无关，也按 `unresolved-delivery` 跳过；后续正常新输入的独立回复机会不因这次纠偏终止而被删除。

### 3.2 一次续接与总预算

建议把现有“生成失败恢复最多一次”抽成桥接回合级 `automaticContinuationBudget=1`。生成失败恢复和回复纠偏原子竞争同一个名额，各自最多一次，不允许“原生成 → 失败恢复 → 再纠偏”或“纠偏失败 → 再生成恢复”。关闭纠偏时，原有失败恢复上限和行为保持。

在任何原生状态查询或续接提交之前，先同步占用并持久化名额；检查失败也不归还以再次尝试。`claim` 的唯一键绑定父回合，重复通知、并发评估及进程崩溃不能创建第二次纠偏。持久化失败则终止纠偏，不先提交后补记录。

沿用原 `AbortController`、`ctx.expires`、回合计时器、用量累计、回复批次、每分钟/小时发送额度、连发上限及工具预算；不刷新有效期，不重置额度。原生查询、重新订阅、第二次生成、工具调用、打字、排队和收尾都占用原 deadline。适配器每次请求的超时取剩余时长与原请求上限的较小值；OpenAI 工具轮数必须跨两次 `run` 共享，不能因局部循环从零开始得到双倍预算。

余量不足时记录 `budget-exhausted`，不延后调度，不通过新聊天回合或后台任务补发。不能用提高 `turnTimeoutMs` 作为自动纠偏的隐式配置迁移。

### 3.3 提醒内容与权限

仅在原兼容会话中提交短的固定续接提醒，携带当前决策回执或内部复核资格的引用及已预留 requestId，不附第一轮 assistant 正文，不重放用户输入或任何 `tools/call`。A 提醒重新核对已登记的决定；B 提醒重新判断是否应回复，不能声称模型已决定发送。两者都允许选择沉默或延期。

复核路径可使用以下固定文案，回合绑定与 requestId 由程序单独提供，不由第一轮正文拼接：

> 上一轮已正常结束，但本回合尚未调用任何工具，普通 assistant 文本不会发送到 QQ。请复核本轮已展示的新消息：如果仍决定回复，使用已启用的 QQ 发送工具；如果选择不回复或暂缓，登记 silent 或 defer 后结束。此次复核不是新来信或新的授权，不恢复回复额度，不要求必须回复。

提醒禁止重做成功工具工作、重发已有或未知投递、另开话题；首版 B 本就排除已有工具调用。

运行时永不自动转发 assistant 文本，也不从正文提取参数替模型调用工具。第二次仍只输出普通文字就结束并记录 `still-no-send`；不会再提醒、发兜底 QQ 文本或触发定时任务。登记沉默或延期时记 `declined`，不能记成修复失败后再次重试。本分支不借用 `failureNotice`；原生成正常完成并占用纠偏名额后，即使原 deadline 在原生查询或复核阶段耗尽，也须在失败通知入口明确阻止发送兜底文字。原生成阶段本就失败/超时的既有通知规则仍按原契约处理，并保留防重。

保留会话的原工具 schema，执行层将纠偏阶段能力限制为原有权限的子集：当前发送工具、回执查询、决策撤销及必要的只读核对；新外部请求、写记忆/Self、运维或其他副作用工具不因提醒被重做。可发现工具也取该子集，但不能修改原生动态工具契约来获得新会话。

`privateRead`、`disclosureTaint`、已批准 `grants`、外部请求授权、来源 ID、媒体保护和读取边界均保留，新增读取继续累计保护。原授权绑定的角色、聊天、来源和有效期不得扩大；等待审批时直接退出纠偏。不能另建“干净 ctx”、复制正文到普通记忆或先清除保护再发送。受保护工作提交/批准及其 `sent:false` 永不启动纠偏。

## 4. 并发、身份与发送幂等

**新消息：** 为聊天维护可信输入代际；输入登记与纠偏 `claim` / 发送准入使用同一角色与聊天的顺序约束。决策回执与复核资格均绑定实际事件集合，不是可被模型提前推进的 `readThroughSeq`。出现新有效输入、绑定输入撤回或可信的附件/语音内容更新时，使旧决定或复核资格失效；纠偏提交前发现就跳过，生成过程中发现就撤销纠偏能力并阻止旧工具调用。保留原 `pendingWakes`，由下一次正常唤醒处理，不把新消息塞进旧纠偏 prompt，不重放旧发言。纯内部记账事件不增加输入代际。

**最后发送边界：** 不能只依赖现有大于三秒打字等待的新输入检查。在纠偏工具准入、打字结束、连接发送队列出队和 attempt 事务前核对回执/输入/配置代际；从最终检查到网关调用之间不插入可让新输入越过的异步等待。新输入在网关请求已发出之后到达时不能撤回现实中的发送，只记录真实回执并禁止后续段/投递，不能将成功降为未发。

**暂停与身份：** 继续执行和每次发送都使用现有 `assertActive`、`allowed`、工具开关、静默、账号及披露检查；全局/角色/聊天暂停、隔离、白名单变化、断线、重配置、升级排空、重置、退休及停止均优先取消。保留原暂停意图，不能自动解除。迟到事件、工具与 `saveSession` 必须绑定连接代际、会话 ID、当前原生回合 ID及阶段；旧 `completed` 不能结束纠偏，旧能力不能恢复归档会话。

**发送调用与 attempt：** 纠偏最多准入一次 `qq_send` 或 `qq_send_burst` 调用，准入同步预留，阻止模型并行发起两条独立回复。提醒提供本轮专用的稳定 requestId，执行层核对一致性；连发仍采用原来的子 ID，逐条走统一发送器。该预留只限调用次数，不额外预扣发送额度；实际 attempt 仍由发送器事务预留现有预算及账本。

同 ID 同载荷保留现有成功回执查询语义，不增加实际发送；同 ID 不同载荷冲突。`pending` / `unknown` / `failed` 不换 ID、不改文案/媒体/目标重发。一次连发可以在原允许上限内继续未执行的段，但发生失败、未知、暂停、新消息或过期就停止，不重新进入该连发，不补齐未发后缀。语气提醒或参数错误导致这次调用未到网关时也不自动增加第二次准入。

原始发送阶段若已有任何调用或 attempt，本就不得进入纠偏。后端恢复的 `recoveryDeliveryBlocked` 仍覆盖所有出口，纠偏不能清空它；新增阶段限制也必须落到统一投递边界，不能只检查两个文字工具。后续真正的新输入仍按原回复批次和去重规则处理。

## 5. 后端适配与会话兼容

| 后端        | 建议适配与准入要求                                                                                                                                                                                                                                                   |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Codex       | 捕获匹配 `item/completed` 的输出类型/非空标记，不存正文；成功终态与所有桥接工具完成后报告证据。续接前只读 `thread/read` 核实原线程 idle、最后一轮 ID 与正常 `completed` 匹配，再在同线程 `turn/start`。新增正常完成校验，不能伪造 failure 使用现有 `recoveryReady`。 |
| DSH         | 从匹配的 `assistant/message` 与 `turn/end` 收集证据。重新订阅读取快照，核实最后事件是同一正常终态且 `next-turn` / `next-step` 都为空，再提交一次短续接；保留工具守卫及订阅代际。不得把错误快照校验当成功快照校验。                                                   |
| OpenAI 兼容 | 当前已有完整 assistant/tool 步骤落盘；新增每轮终止原因校验，只有正常停止且工具结果完整、持久化完成才报告成功证据，截断/工具轮数耗尽不算正常完成。锁定同一本地会话，在完整历史后追加短续接；不伪称 API 有原生线程 idle 证明。跨请求共享工具轮数、deadline 和用量。    |
| Antigravity | 当前验证同 conversation 的 `SUCCESS`、进程正常退出且关闭旧工具入口。首版只观察，不宣称已支持自动纠偏；后续需验证原会话恢复、每次进程的独立调用身份、完整终态/工具收尾与跨进程预算，才显式开放能力。                                                                  |

不切换提供商、模型或新会话来追求发送。协议证据缺失、不支持正常终态续接或验证时仍忙，一律记录 `unsupported` / `native-state-unverified` 并终止；不周期轮询等待、不猜测成功、不重试状态查询。首个实现阶段建议只对 Codex 开放 `correct`，其他后端逐个通过契约测试后扩展。

可选回调及不改变权限的请求级参数通常不需要退休会话。新增决策工具涉及工具 schema/原生工具集，须按 `session-contract` 比较并安全退休不兼容会话：先归档原经历、来源、交接、回执和取消原因，再由下一次正常新输入重建。不能为本轮纠偏退休后重建并重放。仅修改描述/注解与改变 schema 要按现有兼容规则区分，不能笼统声称开启后会话全不变化。

## 6. 可观测性与配置

保留原 `modelOutcome`，增加独立的 `replyCorrection` 版本化元数据：资格/跳过枚举、触发路径（`decision` / `unclaimed-review`）、决策来源类型、共享额度是否消费、两个原生回合引用、纠偏终态、调用/attempt/确认数量、耗时及剩余预算。例：`missing-decision`、`normal-silence`、`tool-attempted`、`delivery-attempted`、`new-input`、`protected`、`budget-exhausted`、`native-state-unverified`、`still-no-send`、`declined`、`corrected-sent`、`delivery-unknown`、`cancelled`。

汇总按路径区分“观察候选”“符合触发条件”“开始纠偏或复核”“选择沉默/延期”“确认发送”“未知投递”“再次未调用”。输出非空标记不能被当成已决定回复；确认成功计数来自账本。诊断采用现有范围隔离和归一化错误码，新增对外码须登记到 `error-codes.mjs`。日志不得新增 assistant/用户正文、提示词、工具参数/结果、原始 provider 错误、能力凭据、本机路径或保护来源正文；不记录正文摘要或正文哈希来推断回复意图。内部关联 ID 只在受控本角色记录中使用，公开指标不输出 QQ 身份。记录写入失败则停纠偏并给脱敏诊断。

建议配置位于角色 `behavior.replyCorrection`，以下只是未来 schema 示例，不是当前可用配置：

```json
{
  "replyCorrection": {
    "mode": "off",
    "conversations": [],
    "reviewUnclaimed": false,
    "minRemainingMs": 10000
  }
}
```

`mode` 为 `off` / `observe` / `correct`；缺省 `off`，空范围不纠偏。`observe` 只统计当前回合，不登记发送要求、不增加模型请求。`correct` 必须显式选择聊天与适配后端，`minRemainingMs` 只是准入下限，不保证生成完成；最大纠偏次数固定为 1，不提供提高上限的配置。工具开关、模型就绪和 live 模式都不等于管理员批准启用。

`reviewUnclaimed` 缺省 `false`。在 `correct` 下设为 `true`，才允许对第 3.1 节 B 类组合条件成立的回合追加一次复核；`off` / `observe` 下此选项不会产生额外请求。它不配置必须回复规则，不提高回复额度；每次复核仍可选择沉默。A、B 与生成失败恢复共用一个自动续接名额，不能各自再加一次。

只在管理员已选择的 `correct` 范围提供决策工具，并确保原生会话完成必要的工具契约切换；`observe` 不改变原工具目录。纠偏不自动补上原本关闭的发送工具。若决策工具未提供、没有可用文字发送工具，或旧会话尚未采用新工具契约，两条路径都跳过；这样复核时始终有明确登记沉默的出口。

未来实现必须同步 schema、默认配置、示例和配置指南，并说明自动续接额外消耗及覆盖限制。新增决策工具同步定义（strict schema）、处理器、registry、catalog、names、错误码和类型检查范围。开启属于新增自动活动，部署/启用需要后续确认；不能随旧配置升级默认打开，也不自动新增强制回复策略。

## 8. 迁移、安全退休与回退

建议把版本化元数据加入现有 `model_turns` JSON 记录，不增加可执行的补发队列；旧记录缺省为无资格，不能扫描历史 `completed-no-send` 启动纠偏。导出/恢复应保留新元数据和 attempt 关联，导入旧记录时不合成决策、自动名额或新授权；如关联需要新增数据库字段，须先补旧库迁移及导出兼容测试。

启动时将遗留的 `claimed` / `correcting` 标记为中断，不自动续跑。不能复用旧能力；继续沿用运行中会话退出后的安全归档。升级先排空活动回合并保留原暂停状态；会话契约不兼容时按现有退休流程保留经历、Self、日记、记忆、原始来源、读水位与回执。归档失败不能删除会话来源、解除保护或先恢复发言。

快速停止使用 `off`：立即禁止新 claim，正在纠偏但尚未出网关的调用失效；已经发出的请求按真实结果结账。原始正常回合及失败恢复按原有边界结束，不新增补发。代码回退前做一致备份并检查旧配置 schema 是否能读取新字段；必要时只删除新配置项，不删除新记录、attempt、未知回执或保护字段。决策工具退出工具契约时也可能需要安全退休；回退不恢复已退休的旧会话，不重发旧消息，不自动解除暂停。
